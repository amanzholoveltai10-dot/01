# PostgreSQL DBA: от новичка до профи

Это учебный репозиторий. Здесь живёт программа, задания и все твои сдачи.
Работаем как в нормальной инженерной команде: задача → ветка → коммиты → Pull Request → ревью → исправления → merge.

---

## Правила игры (читать до конца, без поблажек)

1. **Дедлайн — это дедлайн.** У каждого задания есть дата и время (по твоему местному времени). PR, открытый в 00:01 следующего дня, — просрочка.
2. **Страйки.** Просрочка = 1 страйк. Сдача «на отвали» (не выполнены обязательные пункты, код/конфиг не проверен на живом кластере) = 1 страйк.
   - 2 страйка в модуле → дополнительное штрафное задание по этому модулю.
   - 3 страйка в модуле → модуль проходится заново, со следующим модулем не работаем.
3. **Merge только после моего Approve.** Пока я ставлю `Request changes` — правишь в той же ветке и пушишь, PR обновится сам. Новый PR на то же задание не открываем.
4. **Никакого копипаста без понимания.** На ревью я буду спрашивать «почему так?». Ответ «так было в статье» = PR отклонён.
5. **Всё проверяется руками.** Любая команда, конфиг или вывод в PR должны быть реально выполнены на твоей машине. Вставляй настоящий вывод, а не выдуманный.
6. **Объяснения своими словами.** Теорию пишешь сам, на русском, простыми фразами. Если не можешь объяснить — значит не понял, иди перечитывай.
7. **Если застрял больше 40 минут** — не сиди молча. Пиши вопрос в PR (комментарием) или мне в чат, с тем, что уже попробовал. Застрять не стыдно, молча сорвать дедлайн — стыдно.

## Как сдавать задания

Полная инструкция — в [docs/00-git/README.md](docs/00-git/README.md). Коротко:

```bash
git switch main
git pull                                  # свежая версия main
git switch -c hw/01-psql                  # ветка под задание
# ... работаешь, коммитишь маленькими шагами ...
git push -u origin hw/01-psql             # отправляешь ветку на GitHub
```

Дальше на GitHub: **Compare & pull request** → заполняешь шаблон → присылаешь мне ссылку на PR.

## Программа

Ориентировочно 7–8 месяцев при 8–10 часах в неделю. Сроки модулей — плановые, сроки заданий внутри модулей — жёсткие.

| # | Модуль | Длительность | Что ты будешь уметь в конце |
|---|--------|-------------|------------------------------|
| 0 | **Git и PostgreSQL на Linux** | 1 неделя | Сдаёшь работы через PR. Знаешь версии и все пути кластера в Debian/Ubuntu, отличаешь reload от restart, правишь `postgresql.conf` и `pg_hba.conf` на живом кластере |
| 1 | **psql и консольные утилиты** | 2 недели | Мета-команды `\d*`, `\l`, `\du`, `\x`, `\timing`, `\watch`, `\set`, `.psqlrc`; `createdb`, `pg_ctl`, `pg_isready`, `pg_controldata` — без гугла |
| 2 | **Архитектура кластера и объекты** | 2 недели | Кластер → базы → схемы → объекты; каталог `PGDATA` по папкам; OID, файлы таблиц на диске, системный каталог `pg_catalog` |
| 3 | **Роли, привилегии, `pg_hba.conf`** | 2 недели | Роли и наследование, `GRANT`/`REVOKE`, владельцы, `search_path`; порядок правил в `pg_hba.conf`, методы `scram-sha-256`, `peer`, `md5`, `trust`, `reject`; отладка «no pg_hba.conf entry» |
| 4 | **`postgresql.conf` и параметры** | 2 недели | Контексты параметров (`postmaster`, `sighup`, `user`...), `reload` vs `restart`, `pg_settings`, `ALTER SYSTEM` и `postgresql.auto.conf`, `include`-файлы, приоритет источников |
| 5 | **Логи и траблшутинг** | 3 недели | Пути к логам в Debian/Ubuntu, RHEL, Windows, macOS, Docker; `logging_collector`, `log_line_prefix`, `log_min_duration_statement`; разбор реальных падений; `pg_stat_activity`, блокировки, `pgBadger` |
| 6 | **Внутренности: память, WAL, MVCC** | 3 недели | Процессы сервера, `shared_buffers`, `work_mem`; WAL и checkpoint; MVCC, `xmin/xmax`, VACUUM и autovacuum, bloat, wraparound |
| 7 | **Индексы и планировщик** | 3 недели | B-tree/GIN/GiST/BRIN, `EXPLAIN (ANALYZE, BUFFERS)`, статистика, почему планировщик выбрал не тот план |
| 8 | **Бэкапы и восстановление** | 3 недели | `pg_dump`/`pg_restore`, `pg_basebackup`, архивирование WAL, PITR, `pgBackRest`; восстановление по таймеру |
| 9 | **Репликация и отказоустойчивость** | 3 недели | Потоковая репликация, слоты, синхронная/асинхронная, логическая репликация, failover, обзор Patroni |
| 10 | **Мониторинг и тюнинг** | 2 недели | `pg_stat_statements`, `pg_stat_*` представления, экспортёр для Prometheus, тюнинг под нагрузку `pgbench` |
| 11 | **Эксплуатация и безопасность** | 2 недели | Мажорные апгрейды (`pg_upgrade`), SSL/TLS, аудит, регламенты обслуживания |
| 12 | **Финальный проект** | 3 недели | Продакшн-подобный кластер (primary + реплика + бэкапы + мониторинг) и «учения»: я ломаю — ты чинишь по логам на время |

### Сквозные практики (идут параллельно всем модулям)

- **Ежедневная разминка, 15 минут.** Набор команд из файла-шпаргалки, который ты ведёшь сам, — руками, без копипаста. Это и есть мышечная память.
- **Журнал инцидентов.** Каждая ошибка, которую ты словил и починил, записывается в `incidents/` по шаблону: симптом → что в логе → причина → исправление. К концу курса это будет твой личный справочник.
- **Еженедельный «вопрос на засыпку».** В каждом ревью будет 1–2 вопроса по прошлым модулям. Забыл — повторяешь.
