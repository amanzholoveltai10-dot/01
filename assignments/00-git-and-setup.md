## Шаг 3. Установить PostgreSQL

Учимся на Linux — 90% продакшен-серверов PostgreSQL работают на нём.

- **Linux (Ubuntu/Debian):** `sudo apt install postgresql postgresql-contrib`. Если хочешь самую свежую версию — подключи официальный репозиторий PGDG (инструкция на https://www.postgresql.org/download/linux/ubuntu/).
- **Windows:** поставь WSL2 с Ubuntu (`wsl --install -d Ubuntu` в PowerShell от администратора) и устанавливай PostgreSQL внутри Ubuntu, как выше. Нативный Windows-установщик НЕ используем в этом модуле — до него дойдём в модуле 5, когда будем сравнивать пути в разных ОС.
- **macOS:** допускается Homebrew (`brew install postgresql@<версия>`), но лучше виртуалка с Ubuntu (UTM/Multipass) — пути и сервисы будут как в проде.

Проверь, что сервер работает:

```bash
sudo systemctl status postgresql     # в WSL без systemd: sudo service postgresql status
pg_lsclusters                        # только Debian/Ubuntu: список кластеров
```

## Шаг 4. Первое знакомство с psql и картой файлов

Подключись: `sudo -u postgres psql`

> Почему `sudo -u postgres`? При установке создаётся системный пользователь ОС `postgres` и одноимённая роль-суперпользователь в БД. По умолчанию в `pg_hba.conf` для локальных подключений стоит метод `peer`: PostgreSQL спрашивает у ОС, под каким пользователем запущен процесс, и пускает, если имя совпадает с именем роли. Подробно разберём в модуле 3.

Выполни и **сохрани реальный вывод**:

```sql
SELECT version();
\conninfo
SHOW data_directory;
SHOW config_file;
SHOW hba_file;
SHOW logging_collector;
SHOW log_directory;
SELECT pg_current_logfile();
```

В Debian/Ubuntu `pg_current_logfile()` скорее всего вернёт пустоту — это не ошибка. Выясни, куда тогда пишутся логи (подсказка: посмотри `ls -l /var/log/postgresql/` и подумай, кто туда пишет, если `logging_collector = off`).

Также выполни в терминале (не в psql) и сохрани вывод:

```bash
ps -ef --forest | grep [p]ostgres
sudo ls -la <твой data_directory>
```
