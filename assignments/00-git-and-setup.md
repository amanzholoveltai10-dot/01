## Часть 4. Лаба по `postgresql.conf` → `config-lab.md`

**4.1. Откуда взялось значение.** Выполни:

```sql
SELECT name, setting, unit, context, source, sourcefile, sourceline, pending_restart
FROM pg_settings
WHERE name IN ('max_connections','shared_buffers','work_mem','port',
               'listen_addresses','log_min_duration_statement','data_directory');
```

Для каждой строки объясни колонки `context` и `source`. Отдельно объясни, что значит каждый `context`: `internal`, `postmaster`, `sighup`, `superuser`, `user`. Это ключевая вещь: от неё зависит, хватит ли reload или нужен restart.

**4.2. Параметр с `sighup` — меняем через reload.**
1. В `postgresql.conf` выставь `log_min_duration_statement = 0` и `log_connections = on`.
2. `SELECT pg_reload_conf();`
3. Покажи: новое значение в `pg_settings`; строку о получении SIGHUP в логе; новое подключение в логе; выполненный запрос с длительностью в логе.

**4.3. Параметр с `postmaster` — нужен рестарт.**
1. `ALTER SYSTEM SET max_connections = 150;`
2. Покажи содержимое `postgresql.auto.conf`.
3. Сделай reload и покажи `pending_restart` в `pg_settings`. Почему значение не применилось?
4. Сделай restart, покажи новое значение.
5. `ALTER SYSTEM RESET max_connections;`, restart, убедись, что вернулось старое значение.
6. **Ответь:** если один и тот же параметр задан и в `postgresql.conf`, и в `postgresql.auto.conf`, какой победит и почему? Почему `postgresql.auto.conf` нельзя править руками?

**4.4. Ломаем конфиг специально (траблшутинг).**
1. Сделай бэкап `postgresql.conf`.
2. Допиши в конец строку с опечаткой: `shared_bufers = 256MB`.
3. Сделай reload. Найди ошибку в логе и в `SELECT * FROM pg_file_settings WHERE error IS NOT NULL;`. Работает ли сервер?
4. Исправь опечатку на `shared_buffers = 99999GB`. Сделай **restart**. Сервер не поднимется.
5. Найди причину **тремя способами**: `pg_lsclusters`, `journalctl`, файл лога. Приложи реальные строки.
6. Откати конфиг из бэкапа, подними сервер, покажи `pg_lsclusters` в статусе `online`.
7. **Ответь:** почему опечатка в имени параметра при reload не уронила работающий сервер, а неверное значение при restart не дало ему подняться? Какое правило отсюда следует для продакшена?
